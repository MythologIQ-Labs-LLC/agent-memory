# Code of Conduct

Agent Memory is a technical and research-oriented project. Contributions are expected to improve the quality of the architecture, evidence, implementation guidance, or conformance model.

## Expected conduct

Contributors should:

- critique ideas, evidence, implementations, and decisions rather than attacking people;
- distinguish verified facts from assumptions, hypotheses, and preferences;
- disclose meaningful conflicts of interest when advocating for a product, benchmark, paper, or implementation;
- preserve source attribution and reuse-rights boundaries;
- report security-sensitive findings through the private process described in `SECURITY.md`;
- accept that strong counterexamples and contradictory evidence are legitimate contributions;
- avoid discriminatory, threatening, harassing, or deliberately humiliating behavior;
- avoid flooding issues or pull requests with repetitive, automated, or low-signal content;
- respect maintainer requests to narrow scope, provide evidence, or move unrelated discussion elsewhere.

## Technical disagreement

Disagreement is expected. This repository is specifically designed to let doctrine be challenged by better evidence.

Useful disagreement looks like:

```text
claim
-> evidence or counterexample
-> affected boundary
-> reproducible consequence
-> proposed correction
```

Less useful disagreement is repetition, credentialism, personal accusation, or treating confidence as a substitute for evidence. The repository already has enough doctrine about that particular failure mode.

## Enforcement

Maintainers may edit, hide, lock, or remove contributions and may restrict participation when behavior materially degrades safety, collaboration, or the technical record.

Enforcement should be proportional to the behavior and should preserve useful technical evidence when practical.

## Scope

These expectations apply to repository issues, pull requests, reviews, discussions, and other project-controlled collaboration spaces.
