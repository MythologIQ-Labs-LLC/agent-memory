## Executive Summary

The six tranches are implementable on seams that already exist, but every one of them hits the same structural fact: the public `AgentMemory` facade composes a fixed recall path (lexical BM25 over domain-eligible facts, exact logical identity, shared-evidence neighbours when the substrate supports them), ranked after admission by policy 3.1.2, and nothing the facade builds can accept a vector retriever, a graph retriever, a return budget, or a ranking variant. The semantic vector route (#456) and typed-graph traversal (#461) are real, tested code that the facade never reaches; no production representation provider exists and no embedding library is a dependency. Two corrections to the diagnosis that opened #668: the shipped ranking policy is **3.1.2** (not 3.0.1) and the redesigned #583 is **merged** (PR #634); only the superseded draft PR #587 is still open. Runtime Baseline v1 has no documented versioned-change path: its checker is a byte diff with no allowance for a policy or contract bump, so every tranche needs a successor-baseline procedure before it can merge. Nine drifts between doctrine documents and code are recorded below.

## Findings

### A. Semantic vector route and facade composition (`fact-vector-route-seam`)

- **Route constants**: route id `semantic_vector`, metric `cosine`, posture `deterministic_rebuild_from_canonical` (reference/agentmem_ref/runtime/vector_retrieval.py:29-31).
- **`VectorRepresentationSpec`** is a frozen dataclass with `representation_ref`, `representation_version`, `config_digest`, `dimensions`, `deterministic_rebuild`, `rebuild_posture`, `authority_effect`; `__post_init__` refuses empty ref/version/digest, `dimensions < 1`, `deterministic_rebuild=False`, any other posture, and any authority effect but `none` (vector_retrieval.py:34-66). The docstring asks a model-backed provider to bind model/runtime/config identity in `config_digest`; nothing enforces more than non-emptiness (vector_retrieval.py:36-42, 55-56).
- **`VectorRepresentationProvider`** is a plain Protocol with two members: `spec` (property) and `embed(text) -> tuple[float, ...]`. No batch, no async (vector_retrieval.py:69-75).
- **`NativeVectorCandidateRetriever(representation, *, minimum_similarity=0.0)`**; `available_for(substrate)` is `isinstance(substrate, AllFactsTemporalGraphPort)`; `search(substrate, query, *, group_id, candidate_limit)` embeds the query once, then loops over every `substrate.all_facts()` in the group and calls `embed(fact.fact_text)` on each, on every query; hits with similarity at or below the floor are dropped; sorted by `(-similarity, candidate_ref)` and truncated (vector_retrieval.py:110-191). **There is no cache, index, persistence or ANN**; "deterministic rebuild" means recompute per query (vector_retrieval.py:113-117, 169-174). The route does no domain-eligibility prefilter, unlike lexical `eligible_search` (vector_retrieval.py:169-171 vs runtime/adapter.py:150-170); admission re-checks every candidate.
- **`AllFactsTemporalGraphPort`** is implemented by the in-memory substrate (state/substrate.py:241, 442), SQLite (`SELECT * FROM facts ORDER BY uuid`, state/sqlite_substrate.py:410, 808-810) and the Graphiti driver (state/graphiti_driver.py:177).
- **Composition hook**: `DeterministicMultiRouteRecallPlanner(adapter, *, vector_retriever=None, vector_candidate_limit=16)`; no `graph_retriever` parameter (runtime/runtime_composition.py:141-152). Its ranking policy `MULTI_ROUTE_RANKING_POLICY` orders routes `(semantic_vector, shared_evidence_neighbor, lexical)` with BM25 over the admitted set and has no typed-graph stage (runtime_composition.py:119-125). `ConfiguredCompositionRuntime.create(..., vector_retriever=None)` forwards the retriever (runtime_composition.py:375-392).
- **The durable runtime drops it**: `SQLiteConfiguredCompositionRuntime.create` and `.recover` take no `vector_retriever` and construct `cls(durable_runtime=..., plan=...)`, so the retriever is always `None` (runtime/sqlite_composition.py:16-47).
- **The facade cannot reach it**: `AgentMemory.open(path, *, tenant, actor_id, charter_version, scope, purpose, config_path, qualification_path, verifier_registry)` has no retriever or representation parameter and builds the SQLite runtime (api/surface.py:276-289, 319-335). The runtime configuration profiles and fixtures contain no vector configuration.
- **`ControlledRecallPlanner(adapter, *, controller=None, vector_retriever=None, graph_retriever=None)`** is the only planner that composes all five routes with per-route budgets (runtime/recall_control.py:515-532; budgets at 422-445: lexical `min(32, max(8, 4T))`, vector `min(24, max(8, 4T))`, graph `min(24, max(4, 8R))`). Its only non-test user is the benchmark harness (harness/retrieval_quality_benchmark.py:367-375).
- **Pre-admission order is route insertion order, not score order** (recall_control.py:710-716; runtime_composition.py:247-253).
- **Representation providers**: only hand-written lookup tables in tests (reference/tests/test_native_vector_retrieval.py:107-122, 433-443; test_native_vector_correction.py:85-101; test_retrieval_quality_benchmark.py:39-63). `DeterministicEmbedder` (harness/mem0_comparator.py:47-66) is an 8-dimension SHA-256 hash embedder for the Mem0 comparator and does not implement the protocol. No non-test caller constructs `NativeVectorCandidateRetriever`.
- **Dependencies**: `[project] dependencies` are jsonschema, cryptography, rfc8785; the only extra is `comparators` (pyproject.toml:12-22). `reference/requirements.txt` pins no numpy, torch or embedding library (requirements.txt:3-7). numpy is imported by harness modules (harness/long_horizon_benchmark.py:10 and others) and installed only in CI (.github/workflows/long-horizon-memory-benchmark.yml:20, 93-94).
- **The long-horizon "representation families" are visual**: synthetic video with pooled-pixel and ridge readouts, and a pinned V-JEPA 2.1 frozen encoder (reference/run_vjepa2_operational_comparator.py:30-113; workflow pins commit `45d025f6…` and the checkpoint sha256). They are unrelated to the text vector route.

### B. Post-admission ranking attachment (`fact-ranking-attachment`)

- **Correction**: the active policy is `ExplicitCurrentConstrainedRankingPolicy`, `POLICY_VERSION = "3.1.2"` (runtime/temporal_order_constraints.py:47, 279-296), a subclass of `PostAdmissionRankingPolicy` (`"3.1.1"`, runtime/ranking_policy.py:82-83). Redesigned #583 is merged (PR #634, `a0e6807`) and #584 is merged (`f2aef57`); the ranking module records "Since 3.1.1 (#583)" (ranking_policy.py:37-43). Draft PR #587 (`fix/583-temporal-intent-relevance-separation`) is superseded but still open.
- **Entry point**: `PostAdmissionRankingPolicy.rank(admitted, hits_by_candidate, fact_lookup, query, intent) -> (ordered_refs, evidence)` (ranking_policy.py:507-567). Stages are lexicographic, not fused: temporal applicability tier (only when `intent.orders_temporally`), route corroboration count, exact identity, per-route native score in declared order (lexical = BM25 over the admitted set, statistics from admitted texts only, terms summed in sorted order for #576 determinism), temporal order, sha256 fallback (ranking_policy.py:156-207, 380-391, 453-502). 3.1.2 appends unknown-basis tie neutralisation and pairwise exclusive-slot constraints, active only under the explicit-current profile (temporal_order_constraints.py:102-113, 298-363, 390-409). `route_scores_cross_comparable` is `False` (ranking_policy.py:400).
- **Call path**: `AgentMemory.recall` (api/surface.py:691-757) resolves intent (:715), calls `runtime.multi_route_recall` (:728-733); the SQLite runtime wraps `recall_planner.recall` in `run_governed_read` (runtime/sqlite_composition.py:88-106); the planner runs routes (runtime_composition.py:186-245), deduplicates (:247-253), admits once through `admit_preselected_candidates` (:255-264; runtime/contextual_recall_adapter.py:51-145), then ranks admitted refs only (:266-272). The surface attaches per-candidate `ranking_evidence` and `rank_position` but not the top-level policy identity (surface.py:734-757).
- **Ranking evidence per candidate**: routes, corroboration count, exact identity, route scores, `metabolic_evidence: not_used`, temporal evidence and applicability, lexical relevance score and the `lexical_temporal_guard` block, rank position, policy id and version (ranking_policy.py:422-441, 533-566); 3.1.2 adds constraint and competition fields (temporal_order_constraints.py:413-453).
- **Variant seam**: `VARIANTS` and `apply_ranking_variant()` apply `dataclasses.replace` to the three planner policy constants (reference/benchmark_ranking_variants.py:15-55); validated knobs are `temporal_regime`, `lexical_relevance`, `lexical_anti_laundering`, `unspecified_intent_order`, `stable_fallback` (ranking_policy.py:364-378). The AgentMemBench runner applies and records it (reference/run_agentmembench.py:763, 828-832). The seam is evaluation-only and cannot select a different stage set.
- **Cue masking on main (#583)**: the query is never rewritten; a per-candidate mask applies only when the candidate's persisted `markers.self_claims` intersect currentness, instruction or supersession, and only under `query_conditioned` with the guard enabled (ranking_policy.py:36-43, 88, 128-153, 526-530). The final #580 replay records `temporal_self_claim_rank_influence_count = 0` (reports/benchmarks/temporal-currentness/final-policy-3.1.1/README.md:68-76).

### C. Public recall result shape (`fact-facade-return-shape`)

- **`AgentMemory.recall(query, *, logical_memory_refs=(), target_domain_refs=None, principal_ref=None, project_ref=None, task_ref=None, purpose=None, temporal_intent=None, reference_time=None)`**; no k, limit or budget parameter (api/surface.py:690-703).
- **Result envelope**: `contract.result("recall", CURRENT, candidates=…, admitted=…, admissions=…, candidate_policy=…)`; `admitted` is the full `ranked_admitted`, untruncated; each `admissions[c]` carries the decision plus `route_provenance`, `admission_basis`, `rank_position`, `ranking_evidence`, `refusal` (surface.py:734-757). `routes_executed`, the policy identity, temporal intent and sufficiency are present on `MultiRouteRecallResult` (runtime_composition.py:96-113) and dropped by the facade.
- **Contract**: `CONTRACT_VERSION = "1.3.0"`, additive-minor compatibility, a higher minor is `MIGRATION_REQUIRED` (api/contract.py:21, 50-64); every result is validated against `schemas/api-result-envelope.schema.json`, which is `additionalProperties: false` at the root with a `contract_version` enum 1.0.0 to 1.3.0 and a closed `candidate_policy` object (schema :7, :14-21, :128-145, :234-244); the recall-context schema is likewise closed (schemas/api-recall-context.schema.json:7-40). A budget input or truncation metadata therefore needs schema changes and a contract version bump. `candidate_policy` today carries no identifiers or counts (docs/44-public-api-contract.md:85-90; runtime/adapter.py:138-147).
- **Tests that pin the shape**: reference/tests/test_api_contract.py:38-51 (version 1.3.0; 1.4.0 is `MIGRATION_REQUIRED`), :110-114 (envelope); test_api_surface.py:174-187; test_developer_facade.py:50-137; plus test_api_history_posture, test_recall_authority_record, test_domain_eligibility_prefilter, test_post_admission_ranking_policy, test_retrieval_quality_benchmark, test_continuous_retrieval_regression, test_rc_cognitive_memory_scenario, test_structural_mutation_governance, test_agentmembench.
- **Bridges truncate benchmark-side**: the AMB bridge applies k after full admission and ranking (reference/amb_agent_memory_bridge.py:214-234); the LongMemEval runner returns every admitted item and truncates only in scoring at k in {1,3,5,10,30,50} (reference/run_longmemeval.py:49, 363-370, 534-550). On lane v2 the control returned about 45 of 48 session items per question.

### D. Currentness and the write-time interpreter (`fact-currentness-path`)

- **Query intent** interpreter 1.1.0 (runtime/temporal_intent.py:82); `orders_temporally` only for explicit or high-confidence inferred intent (:322-332); `as_of` without a target raises (:319-320).
- **Declared inputs**: writes accept `valid_from`, `valid_until`, `observed_at` as caller-declared ISO-8601 (temporal_intent.py:643-674; surface.py:463-476, 512-528; stored at runtime/adapter.py:574); recall accepts `temporal_intent` and `reference_time` (surface.py:701-702).
- **With nothing declared**: the only clock is `transaction_time` from `created_at` (ranking_policy.py:240); the label is `unknown_temporal_basis`, which is never demoted (:321-322); base 3.1.1 orders unknowns newest-first by write clock under current intent (:466-467); 3.1.2 removes that preference only in the explicit-current profile (temporal_order_constraints.py:331-363), so inferred-current cues (`latest`, `most recent`) still get newest-first.
- **#584 pairwise constraints** need a persisted `state_change_candidate`/`conflict` relation and one side `applicable` versus `unknown` (temporal_order_constraints.py:151-162, 200-207). With no declared validity nothing is ever `applicable`, so no edge ever fires.
- **Supersession is lifecycle, not ranking**: `_supersede_current` runs only for a committed `correction` (runtime/adapter.py:381-383, 485-532); superseded facts are refused at admission unless caller-declared historical mode (adapter.py:897-948); a declared `valid_until` never refuses at admission (temporal_intent.py:647-650).
- **Write-time interpreter** 1.1.0 / classifier 1.0.0 (runtime/proposition_semantics.py:54-57): `interpret_write` (:600-690), `classify_write` (:826-895), called from `GovernedMemoryAdapter._write` (adapter.py:575-576, 600-635); infers entity/property/value status, cardinality, hedges and self-claims, scoped aspect, self-validity windows (relative forms need a caller `observed_at` anchor), and relations/proposals that are never auto-applied (:855-893).
- **Measured**: known precision 0.800 / recall 0.148; ambiguous 0.210 / 1.000; unknown 1.000 / 0.848; 46 of 54 gold-known turns come out ambiguous; strict slot/value conformance 0 (docs/61-write-time-proposition-semantics.md:165-183).
- **AgentMemBench currentness mechanism, verified with pure-function calls**: five templates write old then new text as separate logical targets with no temporal fields and search top-1 (reference/run_agentmembench.py:316-333, 429-464); all five queries resolve to explicit current, so the 3.1.2 profile is active; every pair classifies as `state_change_candidate`; admitted-set BM25 picks the old text in four of five templates, matching the dashboard's 0.20 / 0.80; the result is decided at the BM25 stage and no temporal stage is reached. No 3.1.2 AgentMemBench or LongMemEval replay is committed.
- **Levers**, each a ruling, not a tweak: (a) a 3.1.3+ policy letting a persisted exclusive same-slot `state_change_candidate` order the change-asserting write over an unknown rival, which conflicts with the "untrusted change evidence creates no edge" rule (temporal_order_constraints.py:13-14) and the self-promotion rule (docs/62-lessons-learned-evidence-and-currentness.md:38-44); (b) host-declared `valid_from` plus `reference_time`, which makes the existing #584 edge fire but is a profile adaptation; (c) explicit `apply_semantic_proposal` (surface.py:595-636), automatic application being ruled out (docs/62:46-50); (d) the stale win in the location template comes from the old text's own word "currently", which the #583 mask does not touch (ranking_policy.py:147-152).

### F. Runtime Baseline v1 change mechanism (`fact-baseline-mechanism`)

- **Pins**: runtime revision `f2aef57…`, public contract 1.3.0, active ranking policy 3.1.2 over base 3.1.1 (reports/runtime/baseline-v1.json:8-14, 20, 26-33); read semantics declares candidate routes `lexical, exact_logical_identity, shared_evidence_neighbor, semantic_vector` (:71) and lists typed-graph traversal and metabolism as `native_qualified` (:85, :88).

The source boundary protects `pyproject.toml` and `reference/agentmem_ref`, excludes only `evaluation/**`, and treats new subtrees as runtime-bearing (reports/runtime/baseline-v1-source-boundary.json:5-27); its only change path is "a future reviewed boundary revision" for path classification (:31).
- **Checker**: `git diff --exit-code <frozen> <candidate> -- <protected> <exclusions>`; exit 1 is FAIL, otherwise PASS; it refuses a boundary lacking `baseline_mutation=false`, `authority_effect=none` or a 40-hex revision (scripts/check_runtime_baseline_equivalence.py:28-34, 62-97). **It is pure byte equivalence with no notion of an allowed versioned change.** A second, stricter script diffs all of `reference/agentmem_ref` with no exclusion against the public-Gauntlet `verified_head` and checks that `CONTRACT_VERSION`, `POLICY_VERSION`s and route constants at the frozen commit match the JSON, reading constants only, not facade wiring (scripts/validate_runtime_baseline_source.py:66-88, 99-146, 190).

- **No documented procedure for a deliberate runtime change**: reports/runtime/baseline-v1.md has no "changing the runtime" section (closest :101, "immutable RC1 runtime target"); docs/66 has none; contributor guidance is defensive only (docs/CONTRIBUTOR_ARCHITECTURE.md:241-249).
- **Precedent for versioned ranking changes**: every change bumps `POLICY_VERSION` and is recorded in ranking evidence (docs/56-benchmark-gauntlet-remediation-evidence.md:100); #576 took 3.0.0 to 3.0.1 with a replay artifact (docs/56:503-512); docs/60 requires a new tier to be a separately versioned decision with gauntlet acceptance (docs/60-temporal-currentness-qualification-gauntlet.md:208, 245-246); #584 landed as 3.1.2 and the baseline binds it to replay workflow 37175525822 (baseline-v1.json:133-138). The de facto path is: version bump in the module, frozen replay artifact, gauntlet acceptance, baseline identity. Post-publication, any such bump also fails the equivalence check until a successor baseline is published.

## Recommendations

1. **(P0, blocks every tranche) Define the successor-baseline procedure before any runtime change**: a Runtime Baseline v2 artifact bound to a new frozen revision, the equivalence checker reporting "candidate differs from v1 at paths X, bound by baseline v2 at revision Y" rather than FAIL, the stricter validator reconciled with the exclusion policy, and a doc section "changing the runtime" in reports/runtime/baseline-v1.md. This is the first deliverable of #674 and a prerequisite node for scopes 1, 2 and 4 (`prereq-lane-v3-ids` depends on it).
2. **(P0, #669) Thread a `vector_retriever` from `AgentMemory.open()` through `SQLiteConfiguredCompositionRuntime.create/recover`** and give the vector route a domain-eligibility prefilter and a derived, versioned vector store keyed by `(fact uuid, representation spec)` so "deterministic rebuild" stops meaning "recompute per query". The provider itself is a pinned local model behind the existing protocol; the dependency posture is an owner decision (`decision-embedding-dependency`).
3. **(P1, #673) Attach a fusion stage between route hits and the lexicographic policy** (the ranking policy's per-route max-score stage is where scores first meet) and version it as 3.2.0 with its own evidence block; keep the lexicographic temporal stages above it. The reranker is a later, separately versioned stage.
4. **(P1, #670) Add a return budget as contract 1.4.0**: an optional `budget` input in the recall context schema, `candidate_policy` gaining counts and the applied budget, `admitted` truncated only after ranking, the full admitted count always present.
