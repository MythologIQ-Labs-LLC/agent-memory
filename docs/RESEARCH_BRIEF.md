## Executive Summary

Agent Memory is a mature doctrine-and-evidence repository (42 doctrine docs, 35 ADRs, 58 schemas, 64 fixtures, ~120 runtime modules, 861 tests, 58 CI workflows) whose installable runtime does not yet match the 1.0 "supported runtime" objective. The doctrine is strong and validated. The gap is between the reference package as shipped and what a 1.0 consumer would need, and, per the Round 2-3 security work, between the PAMA thesis ("uncertainty may propose; authority constrains") and a base commit, recall, and delete path that trusts caller-asserted authority inputs. Those findings are direct violations of the ecosystem invariants recorded in the owner's discovery session: memory cannot self-authorize, uncertainty cannot become permission, and an integration or caller never inherits the authority of the system it addresses.

**Top 5 critical findings (all empirically reproduced)**

1. **GAP-ARCH-01** No public runtime API boundary. Store/recall/delete exist only through internal module paths; the CLI is diagnostic only; `docs/CONFIGURATION.md` advertises CLI subcommands that do not exist.
2. **GAP-SEC-02** Recall admission across isolation domains is decided by a caller-built `RecallContext` with no authentication, no PAMA decision, and zero audit events; facts with no scope record are admitted, where docs/34 and the JS runtime both reject them. Probe: a `dom-A` fact was admitted to an arbitrary principal with no governance trace.
3. **GAP-ARCH-02** Persistence is an in-memory graph snapshotted to JSON by scraping adapter privates. Only the in-memory substrate is checkpointable. The per-adapter id counter makes two tenants on one shared substrate silently overwrite each other's facts (GAP-SEC-08).
4. **GAP-RT-01** Installed from a wheel, `commit_proposal` raises `FileNotFoundError` on its first audit event. Only one of fifteen fallback-less loaders is on the hot path.
5. **GAP-ARCH-04 / GAP-SEC-03 / GAP-SEC-04** Caller-asserted `review_satisfied` plus any `approval_refs` (including the actor's own id) discharges review and external verification on scope expansion, permanent deletion, and policy mutation; `governed_delete` ignores staleness, target, and tenant and physically removed another tenant's fact; a grant with a tampered expiry and a denied approval edited to approved both verified current.

**Positive posture worth preserving**: GitHub secret scanning, push protection, CodeQL (6 languages), private vulnerability reporting, and Dependabot security updates are all enabled. Direct Python deps are exact-pinned. All 60 most recent `main` runs are green. No `pull_request_target`, every workflow has a `permissions:` block, no `eval`/`exec`/`pickle`, all file writes are atomic with fsync and recovery fails closed on digest mismatch. Tenancy filtering, tombstone and superseded filtering on the governed recall path, stale-decision protection (when opted in), containment enforcement, the composition gate, and the PAMA evaluator core (M0-M5, A0-A5, base table, floors, modifiers, envelopes) are implemented. `reusable_grants` and `decision_overwrite` already demonstrate deriving authority booleans from validated evidence; `structural_pama` already binds policy digests correctly for one operation. The README carries maturity disclaimers at lines 30 and 479. Round 3 sampled 7 of 20 threat-model citations and found zero fabricated references.
