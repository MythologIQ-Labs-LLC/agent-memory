### Merged Rust-shadow evidence

The Rust shadow crate is deliberately not linked into the runtime.

It now independently reproduces three useful classes of deterministic behavior.

#### 1. Ranking / digest primitives — PR #605

- Agent Memory relevance tokenization;
- admitted-set BM25 using the #576 deterministic sorted-term accumulation order;
- exact IEEE-754 BM25 score bits on the qualified Ubuntu CI profile, including an exact tie;
- UTF-8 SHA-256 digest vectors.

Accepted qualification runs include:

- `36457677348`: exact token vectors and BM25 score-bit parity;
- `36458112635`: BM25 parity retained and SHA-256 vectors reproduced exactly.

#### 2. Non-floating canonical JSON bytes — PR #610

Python and Rust reproduce the same frozen canonical UTF-8 bytes and SHA-256 digests for the explicitly non-floating JSON domain:

- null;
- booleans;
- exact integers;
- strings;
- arrays;
- string-keyed objects with deterministic key ordering.

The Rust value model structurally cannot represent floats in this slice, so the qualification cannot accidentally overclaim persistence parity.

Focused qualification run `36485253610` passed, and the complete exact-head repository matrix was green before merge.

#### 3. #591 identity-first candidate prefilter — PR #611

The Rust shadow reproduces the pre-materialization candidate path:

```text
identity/text projection
  -> selected group filter
  -> caller-supplied identity eligibility
  -> lexical overlap
  -> score desc / uuid ordering
  -> materialize survivors
```

Frozen vectors cover wrong-group exclusion, identity-ineligible exclusion, score ties, duplicate query terms, empty stripped queries, current punctuation behavior, and exact score bits.

Focused qualification run `36486001629` passed and the entire exact-head repository matrix was green before merge.

This is a materially stronger signal for a possible Rust kernel because the candidate prefilter is a real hot path introduced by #591, not a standalone micro-utility.

It still does not grant Rust recall-admission or authority responsibilities. Full materialized-fact eligibility and canonical admission remain downstream.

## Determinism gap discovered by #602: #609

The Rust work exposed a real language-neutral persistence issue.

Current canonical bytes are produced by CPython's JSON encoder. `TypedRelation.retrieval_weight` is a finite float, and typed-relation rows participate in SQLite integrity commitments. Therefore CPython floating-number spelling is currently embedded in persisted row hashes, bucket roots, restart verification, and tamper evidence.

This means:

```text
non-float canonical-byte parity
        !=
full persisted-state parity
```

Issue #609 owns the required language-neutral numeric canonicalization and migration contract.

A draft ADR-040 proposal is under review separately. No current runtime bytes or digest schemes have changed.

Until #609 is dispositioned, Rust may continue qualifying deterministic primitives and hot paths that do not rely on unresolved float-bearing persisted bytes, but state/integrity/restart promotion across that seam remains blocked.

## Runtime decision posture

Decision candidates remain:

```text
A. Python remains preferred
B. Python facade + Rust performance/assurance kernel
C. native Rust runtime + Python bindings
D. parallel conformant Python and Rust profiles
```

The evidence has strengthened candidate **B** as a hypothesis, because deterministic ranking, canonical non-float bytes, hashing, and a real candidate-generation hot path all port exactly so far.

That is not yet the decision. The missing evidence is still substantial:

- language-neutral float-bearing persistence canonicalization and migration (#609);
- matched Python/Rust hot-path performance on identical hardware/workloads;
- runtime state/integrity parity;
- minimal `open -> remember -> recall -> restart` parity;
- operational/package/maintenance comparison;
- FFI cost and ecosystem integration cost.

A hybrid Rust kernel remains preferable to a wholesale rewrite if it captures most measurable benefit with substantially less semantic and maintenance risk.

## Current interpretation

Agent Memory has enough internal evidence to justify continuing the RC temporal closeout, but it does not yet have enough competitive evidence to make a serious 1.0 market-position claim.

The Rust evidence is now strong enough that a bounded hybrid kernel deserves serious qualification rather than being treated as a speculative language experiment. It is still not strong enough to justify replacing the Python runtime.

The most important result of the Rust work so far may be the defect it exposed: persistence canonicalization was not fully language-neutral even though the architecture intends the core to be. #609 now makes that hidden implementation assumption explicit and falsifiable.

That is the intended maturity posture: advance the implementation while using cross-language pressure to discover where our supposedly portable contracts are still secretly Python-shaped.
