#### 2. Non-floating canonical JSON bytes — PR #610

Python and Rust reproduce the same frozen canonical UTF-8 bytes and SHA-256 digests for the explicitly non-floating JSON domain:

- null;
- booleans;
- exact integers;
- strings;
- arrays;
- string-keyed objects with deterministic key ordering.

The Rust value model structurally cannot represent floats in this slice, so the qualification cannot accidentally overclaim persistence parity.

Focused qualification run `36485253610` passed, and the complete exact-head repository matrix was green before merge.

#### 3. #591 identity-first candidate prefilter — PR #611

The Rust shadow reproduces the pre-materialization candidate path:

Frozen vectors cover wrong-group exclusion, identity-ineligible exclusion, score ties, duplicate query terms, empty stripped queries, current punctuation behavior, and exact score bits.

## Determinism gap discovered by #602: #609

The Rust work exposed a real language-neutral persistence issue.

Current persistence canonical bytes are produced by CPython's JSON encoder. `TypedRelation.retrieval_weight` is a finite float, and typed-relation rows participate in SQLite integrity commitments. Therefore CPython floating-number spelling is currently embedded in persisted row hashes, bucket roots, restart verification, and tamper evidence.

This means:

```text
non-float canonical-byte parity
        !=
full persisted-state parity
```

Issue #609 owns the required language-neutral numeric canonicalization and migration contract.

A draft ADR-040 proposal is under review separately. No current runtime bytes or digest schemes have changed.

The #609 inventory program has also established that the repository contains multiple canonicalization families, including existing deliberate RFC 8785/JCS identity/evidence surfaces. A persistence-v2 decision must not silently reinterpret those already-JCS-bound identifiers.

Until #609 is dispositioned, Rust may continue qualifying deterministic primitives, integration boundaries, and hot paths that do not rely on unresolved float-bearing persisted bytes, but state/integrity/restart promotion across that seam remains blocked.

## Runtime decision posture

Decision candidates remain:

```text
A. Python remains preferred
B. Python facade + Rust performance/assurance kernel
C. native Rust runtime + Python bindings
D. parallel conformant Python and Rust profiles
```

Candidate **B is now the evidence-backed leading hypothesis**, not merely an architectural preference.

Reasons:

- deterministic ranking/tokenization ports exactly;
- SHA-256 ports exactly;
- non-floating canonical bytes port exactly;
- the real #591 candidate-generation hot path ports exactly;
- the same hot path is about **2.49x faster** in matched same-runner compute evidence.

That is still not an architecture decision. Candidate B must retain enough of that advantage after Python↔Rust integration overhead to be worthwhile, and it must not broaden authority or duplicate lifecycle semantics.

Candidate C remains unsupported by current evidence. Moving the entire runtime to Rust would add persistence, lifecycle, governance, Python-ecosystem, packaging, and maintenance costs that the current evidence does not justify.

Missing evidence remains:

- Python↔Rust FFI/binding overhead and packaging cost;
- how much of end-to-end search latency is actually capturable by the qualified kernel;
- language-neutral float-bearing persistence canonicalization and migration (#609);
- runtime state/integrity parity;
- minimal `open -> remember -> recall -> restart` parity;
- broader operational/package/maintenance comparison.

A hybrid Rust kernel remains preferable to a wholesale rewrite if it captures most measurable benefit with substantially less semantic and maintenance risk.

## Current interpretation

Agent Memory has enough internal evidence to justify continuing the RC temporal closeout, but it does not yet have enough competitive evidence to make a serious 1.0 market-position claim.

The Rust evidence is now strong enough that a bounded hybrid kernel is the leading runtime hypothesis rather than a speculative language experiment. Exact semantic parity plus a matched ~2.49x hot-path speedup is meaningful evidence.

It is still not strong enough to justify replacing the Python runtime. The next decisive question is whether that performance advantage survives a real Python↔Rust boundary and moves end-to-end Agent Memory search materially.

The other major value of the Rust program remains architectural pressure: it exposed that persistence canonicalization was not fully language-neutral even though the architecture intends the core to be. #609 now makes that hidden implementation assumption explicit and falsifiable.

That is the intended maturity posture: advance the implementation while using cross-language pressure to discover where our supposedly portable contracts are still secretly Python-shaped.
