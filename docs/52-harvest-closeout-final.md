# Ancestry and Peer Harvest Closeout

Issue: #470

## Closeout state

The known Agent Memory ancestry and peer harvest is complete for the source set reviewed through 2026-09-25.

Canonical machine-readable record:

```text
reference/fixtures/harvest-closeout-final-v1.json
```

The final matrix supersedes the wave-1 and wave-2 harvest summaries as the current closeout artifact.

This is a snapshot closeout, not a claim that upstream projects will never change. A future release, new repository, or newly relevant mechanism creates a new bounded review. It does not keep this historical harvest permanently open.

## Governing result

```text
implementation ancestry
    != permanent runtime ownership

useful generic mechanism
    -> inspect
    -> validate
    -> classify rights
    -> absorb natively, retain as optional interop, or reject explicitly
```

Agent Memory is the canonical owner of generic memory machinery.

No generic runtime dependency on EvolveAI, CodeGenome, or COREFORGE is required by the harvested end state.

External governance, trust, identity, and verification systems remain optional peers or evidence sources unless an independently accepted decision changes that boundary.

## UOR ecosystem disposition

### UOR Framework and UOR-Addr

Deterministic identity and exact-reference concepts remain optional interoperability lineage. UOR identity does not become memory lifecycle, recall admission, or PAMA authority.

### UOR-R4

The geometric predictive-memory model is not adopted because the reviewed source does not establish a reason to replace Agent Memory architecture.

The useful experimental lesson was narrower: exact-key rebinding, matched controls, stale-value measurement, and negative-result discipline. That lesson is absorbed in the keyed-rebinding/currentness benchmark work from #483/#484.

### UOR Foundry

Foundry's generic scoped-authority, replayable-acceptance, and evidence-honesty lessons are already represented by PAMA, revision-bound qualification, capability maturity, and Agent Memory evidence-depth discipline.

Its broader organization quorum, product-release, and supply-chain machinery remains specialized release engineering rather than generic memory functionality.

### `uor-jcs-nfc`

The inspected revision remains a provisional RC5 publication. Its specific JCS/NFC identity profile is not adopted into Agent Memory today.

One generic lesson was worth harvesting immediately: verification and benchmark checks should prove they can detect controlled mutations rather than merely report success. Agent Memory now has a bounded mutation-integrity harness in:

```text
reference/run_benchmark_integrity_mutants.py
```

The harness verifies that admitted noise, missing gold edges, candidate/admission collapse, ranking damage, and final-admission refusal alter the expected metrics.

A future final `uor-jcs-nfc` publication may be reviewed if direct interoperability becomes useful. That future event does not block this closeout.

### UOR Matmul

Its exact arithmetic/conformance methodology did not expose a generic memory gap beyond existing deterministic evidence practices, so no adoption is required.

### PrismPM

PrismPM was reviewed at exact revision:

```text
73d041a46a4e15127e7fdef1dc16a8d592c5ccd3
```

The repository is dual licensed MIT OR Apache-2.0 at that revision.

Three lessons were evaluated:

1. Authority/source bindings should remain distinct from executable verification oracles, with locked drift refusal. Agent Memory already preserves this separation across source qualification, runtime configuration, estimator evidence, and PAMA authority.
2. Positive/negative corpora and mutation pressure should detect stale, bypassed, changed, or trivially passing checks. This lesson is now absorbed through the benchmark-integrity mutation probes and existing adversarial governance fixtures.
3. Complete OCI release graphs, self-rebuild chains, and deployment/publication closure are useful release-engineering patterns but are not generic memory machinery. They remain specialized external verification/release concerns.

No PrismPM runtime dependency or authority effect is introduced.

## Benchmarking consequence

The ancestry harvest strengthens the benchmark program in two ways.

First, it confirms that Agent Memory should continue measuring retrieval quality, currentness, governance, performance, and consistency separately rather than compressing them into a single score.

Second, the new mutation-integrity probe adds evaluator self-checking around the SWE-ContextBench work. A benchmark pipeline should be able to demonstrate that known bad outcomes are visible to its metrics.

This does not replace the real-world benchmark lane.

#467 remains the protocol-comparable SWE-ContextBench target. The pull-and-run comparison harness and the 99-query / 100-gold-edge runner are ready, but the exact frozen external past-task projection and batch/distractor provenance are still required before a comparable external result can be claimed.

Longitudinal field evidence remains separately tracked by #388 and #408.

## Final answers required by #470

### Have we harvested every materially useful generic mechanism or lesson from the known ancestry and peers?

For the reviewed source set, yes. Every identified generic mechanism is now classified as absorbed, optional interoperability, specialized-source-only, intentionally not adopted, or obsolete/superseded.

### For everything not harvested, is there an explicit reason?

Yes. Non-adoptions are tied to architecture fit, specialization, insufficient evidence, provisional publication state, or the rule that external evidence and identity mechanisms do not become Agent Memory authority.
