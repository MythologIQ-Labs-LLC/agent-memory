**How the runner compares.** `op_result` reads one summary field. `op_mentions` substring-scans the full facade result for the listed tokens (labels resolved to uuids). `history` projects `{current (label), state_version, tombstoned, events (types only), [rejected_values (count)]}`. `history_same_as_unknown`, `op_same_as_unknown` and `recall_same_as_unknown` serialise the whole result (`json.dumps(sort_keys=True)`), replace known fact uuids by labels, fold `ref-N`, ISO timestamps, `facade:<sha>` proposal ids and `content:sha256:<sha>`, replace the target ref by `memory:never` on the probed side, and compare the two strings for equality: a field-for-field comparison of the entire public result against the never-written id. Private reads (`_canonical_history`, `_substrate.get_fact`, `tombstoned_ids`, `_disputed`, `get_episode`, `version_in_effect`, `write_semantics`) are ground truth, not public observables. `delete_version` and `commit_with_episode` are adapter-level calls (`governed_delete`, `commit_proposal`), not public-facade calls; the README says so.

Column key for the tables: **Corr.** = CORRESPONDS / WEAKER / STRONGER / NOT DERIVABLE (relative to the contract sources hashed in the fixture at `560785a8`; "@HEAD" marks a clause that exists only in `docs/44`/`docs/786` at `e5abd116`, added by the freeze commit `a7a81c45`). **Kind** = P (positive control), N (negative control), D (disclosure / indistinguishability test).

## Positive controls (question 1)

Each family contains cases in which the authorised same-scope writer succeeds, so a refuse-everything runtime fails every family: W5 (owner remember/correct/dispute commit; B's own id commits), W4b (owner's `memory:k2`), W6 (`kept_committed`), W8 (B's re-creation and correction commit with v0->v1->v2); L2 (owner re-creation commits and is the only admitted historical fact), L5 (`d1` commits, `memory:f@3` admitted), L4 (`owner_at_gen3`), L6 (`p1`); R3/R5/R6b (B's generation commits with receipts), R4 (`live`, `live-digest` admitted). In addition every `require_committed` step turns a refusal into a scenario error, so the seeding writes are implicit positive controls in all 28 cases.

## Unknown-target indistinguishability (question 2)

`history_same_as_unknown` (W1, W5 both directions, W7, W7b, L6, R2 x2 incl. value probe), `op_same_as_unknown` (W2: correct, forget, permanent forget, dispute) and `recall_same_as_unknown` (L1 x2, R2 x2) compare the **whole** public result as a sorted-key JSON string, after folding fact uuids to labels, `ref-N` ids, ISO timestamps, `facade:` proposal hashes and `content:sha256` refs, and replacing the probed target ref by `memory:never`. A leaked uuid becomes `<label>` and survives folding, so it is detected. What is not compared this way: the former owner's observables against a no-re-creation baseline (W7c, L3, R6b pin tokens or `committed` only), and the live-generation `history` views, which are compared by event type and count, not by payload.

## Restart and deleted-generation closure (question 3)

## What the fixtures prove and do not prove

They prove, at one runtime tree (`a44d1b47`, = `e5abd116`), under one tenant and two project scopes with one actor id, through `AgentMemory` plus three documented adapter-level reads/writes, that 28 scripted scenarios produce the recorded observables, and that the observables listed above equal the never-written case field for field.
