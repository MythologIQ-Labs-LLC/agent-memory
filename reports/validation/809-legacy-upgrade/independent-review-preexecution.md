## 2. Classification rules: decidability and order

Each rule's inputs: (1) `r in fact_scope`; (2) id order; (3) `_scope_refusal`'s isolation/required/project/task gates between the citer's reconstructed context (`domain_refs`, `project_ref`, `task_ref` of its own scope record; actor from provenance) and `fact_scope[r]`; (4) whether every matching isolation domain is a key of `shared_domain_members`; (5) otherwise. All are decidable from durable state only, and the reconstruction claim in §2 holds: `_scope_refusal` reads `scope["domain_refs"]`, `required_domain_refs`, `project_ref`, `task_ref` against `context.target_domain_refs/project_ref/task_ref` and ignores `purpose`, so the context rebuilt from the citer's own scope record is exactly the one `_bound_derivation` would have used at commit (adapter `_writer_context` derives it from the same proposal fields that `_write_scope` stored).

Order and edge cases:
- **Forward and membership-dependent** (e.g. a shared-domain citer citing a later id): rule 2 fires first → `forward_reference`, unbound. Correct: the owner's non-retroactive ruling makes a forward citation bind under no membership; unbinding needs only id order, which is durable, so it is evidence-based, not fabrication.
- **Ineligible and membership-dependent**: rule 3 before 4 → `ineligible_scope`. Correct: required-domain, project and task are necessary conditions independent of membership (`_scope_refusal` would refuse before or after the membership check regardless), so "unreadable under any membership" is provable.
- **Required-domain subsets**: rule 3 applies `required_domain_refs(r) ⊆ domain_refs(F)` exactly as recall does; cross-scope `bd`→`a1` fails it (`project:a` missing from `[tenant:legacy, project:b]`) after the isolation gate passes on the shared `tenant:legacy` domain — so "ineligible_scope via required-domain missing" is the right first-failing gate, and the project gate would fail too. Decidable.
- **Tenant-wide facts** (`domain_refs = (tenant,)`): the match is `{tenant}`, which is never a shared-domain key, so rule 4 does not apply and the edge is `eligible` if project/task pass. Correct and consistent with how recall judges it.
- **Project/task when the citing fact's `project_ref` is its scope** (facade default `project_ref = self.scope`, including `shared:x`): rule 3 compares the citer's `project_ref` with the cited fact's; for the shared store both are `shared:x` (passes), for cross-scope `project:b` vs `project:a` (fails). Decidable; it reproduces the write-time judgement because the stored record *is* the write-time proposal.
- **Rule 4's "governed shared space"** is judged by the **current** key set of `shared_domain_members`. A domain that became shared after the write is classified `membership_undecidable` (conservative, fine). A domain that was shared at write time but whose key was later removed would be classified `eligible` — a fabrication path. No API removes a key (`set_shared_domain_members` assigns, an empty tuple keeps the key), so it cannot happen through the runtime; the record should state this assumption explicitly, and `NoFabrication` relies on the same current map (§4).
- **Rule 1 misclassifies one real case.** "`r` not in `fact_scope` → unknown_reference (an external identifier or an id this store never governed)" conflates two situations: an id the store never governed, and an id the store *did* govern but for which no scope record exists (a store older than `fact_scope`, or a row written below the adapter). For the second, unbinding drops a possibly legitimate dependency without evidence of ineligibility — exactly what the owner forbade. Witnesses that an id was governed exist durably even after purge: a `facts` row, a `fact_memory` entry, a tombstone's `fact_uuid` or lineage. The rule should read: not in `fact_scope` **and** no such witness → `unknown_reference`; governed but without a scope record (or a citing fact without one, which §3 does not address at all) → a quarantined `scope_undecidable` class (kept bound, `legacy_unqualified`). None of the three fixtures contains such a row (every fact has a scope record), so the expected outcomes are unaffected; the rule text and `NoFabrication` are (F-2, F-5).
- **Rule 2 "ids not comparable"** can only arise for keys that are not `ref-NNNN`; every v7-governed fact is `ref-NNNN` from one sequence; the class is a correct fail-closed default.
- **Duplicates in `episode_uuids`**: the classification is per distinct reference; the test at line 209 compares `list(episode_uuids)` to `list(classes)`, which assumes no duplicates (F-8).

## 3. "Kept bound + quarantined + `legacy_unqualified`" versus unbinding

Three readings of the owner's "explicit governed quarantine" of a dependency that cannot be decided:

(a) **Keep bound, label, report** (the record's choice). For: it is the only option that preserves deletion completeness for the edges that *are* legitimate (`sm`: a member's derivation of deleted shared content stays withheld); it drops nothing and asserts nothing new — the binding is the pre-upgrade state, so no read authority is fabricated, only left unresolved; the label is durable evidence that the store is not proven sound and the activation rule blocks v8 over it. Against: for `sc`/`sl` the store keeps asserting a derivation the writer may never have been able to read, and the F-R3-2 oracle keeps answering for those citers to whoever uses the store (activation being blocked does not stop the store being served). The record says this plainly (§4 second bullet), which is the right disclosure.

(b) **Unbind**: treats undecidable as unknown. For: closes the oracle everywhere at once. Against: it is a decision without evidence in the forbidden direction — it releases `sm`-type derivations of deleted content, i.e. it drops legitimate deletion dependencies, and it *does* fabricate: it asserts "the writer could not read it" with no durable witness. This contradicts both "never drop all legacy edges without evidence" and "preservation of legitimately derived deletion dependencies". It should not be chosen.

(c) **Quarantine the citing fact, not only the edge**: keep the edge bound *and* withhold the quarantined citer unconditionally (not only when its source is deleted) until a governed act resolves it. For: it closes the oracle even in unqualified stores (withholding no longer varies with the cited generation's deletion state) while preserving completeness, and it is the most literal "governed quarantine" (the memory is sequestered pending authority). Against: availability — a member's legitimate derivation (`sm`) becomes unreadable to its own writer until resolved; and it changes public reads of legacy rows, which needs its own preregistered expectations.

**What the record should state.** (a) is a sound reading of "explicit governed quarantine" and "never fabricate", and the record's own activation rule makes it defensible; it should **not** unbind. But the record must say explicitly what it only implies: that an unqualified store, although not activatable, still serves the quarantined citers' oracle to its callers, and that (c) is the available stricter disposition if the owner wants the oracle closed in every store at the price of availability of quarantined derivations. The choice between (a) and (c) is the owner's; the record should present it as such rather than silently taking (a). Also: `legacy_upgrade_status()` must expose the quarantined set publicly enough that an operator cannot miss it (the tests read it; the record should say it is a public status, not an adapter internal).
