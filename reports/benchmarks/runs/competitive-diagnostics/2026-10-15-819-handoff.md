# Competitive diagnostic handoff for #819: where external memory systems beat or trail Agent Memory

**Status: candidate analysis of candidate measurements.** The Agent Memory numbers are for the
frozen baseline. No runtime code was changed and nothing here was tuned against benchmark gold.
Case content and gold labels are not reproduced. This document keeps three things apart: what
was **observed** (measured), what is **hypothesised**, and what was **demonstrated** (shown by
an intervention or attribution).

## Cohort and protocol qualifications

| Profile | Systems measured (same harness, inputs, budgets and scorer within a profile) | Capability tier |
|---|---|---|
| LongMemEval-S, 500 questions, session plane (419 scored) | Agent Memory, Hindsight 0.10.2 chunk-only, MemPalace 3.11.0, plus a lexical-overlap control | No LLM, local models only |
| LongMemEval-S, 500 questions, turn plane (419 scored) | Same | No LLM |
| AMB PrecisionMemBench single-turn, 77 cases, protocol A | Agent Memory, BM25, Mem0 OSS explicit, MemPalace, Hindsight chunk-only | No LLM |
| AMB PrecisionMemBench, 77 cases, protocol A | LangMem 0.0.30: 9/77, precision 0.017, recall 0.093 (one run). Graphiti 0.31.1: 9/77, precision 0.066, recall 0.996, Supersession 0/3 with 1 invalidation in 35 episodes (run 1; run 2 running) | LLM at ingestion (local 3B), so separate rows not ranked with the rows above |
| LongMemEval-S, 50-question subset (43 scored) | Mem0 OSS 2.2.1 explicit vs Agent Memory | No LLM |

- **Two protocols, kept apart.** LongMemEval measures whether the evidence is *found*: recall
  and nDCG at depth. AMB measures *selectivity*: every must-include and must-exclude assertion.
  The two are never combined into one ranking.
- **Lexical overlap and BM25 are controls,** not memory products.
- **Hindsight here is its no-LLM chunk mode,** not its LLM product.

### O3. The misses are multi-evidence questions where Agent Memory admits everything but orders badly

On 44 of the 74 questions Agent Memory misses at @5, at least one peer gets full recall:
- 25 are multi-session questions and 13 are temporal-reasoning questions.
- On these 44 questions Agent Memory admits about 46 of a roughly 48-item corpus.
- At least one evidence session is already in its top 5 in 75% of them.
- Full recall reaches 0.55 at @10 and 0.98 at @30.
- 50% of these questions need 3 or more evidence sessions, against 13% of all 419.

### O7. Temporal applicability and correction

- **LongMemEval:**
  - knowledge-update is near parity (Agent Memory 0.972, peers 0.986);
  - temporal-reasoning trails (0.803 against 0.858–0.882).
- **AMB:** Supersession chain exclusion is 0/3 for every no-LLM system.
- **Graphiti:** in its smoke, the local 3B model did not invalidate a superseded fact. Graphiti
  marks contradictions with an LLM judgement, and with this model it did not mark that one.
  The AMB-77 run will show this at scale.

### O8. Input asymmetry to keep in mind

On AMB, Agent Memory's bridge passes document timestamps (`observed_at`). The MemPalace,
Hindsight and LangMem bridges do not; Graphiti receives them as `reference_time`. Agent Memory's
AMB lead is in alias and fuzzy matching, so this is unlikely to drive it, but it is an input
difference. On LongMemEval, no bridge passes session dates. *(Disclosed after independent
review.)*

## Hypotheses (not demonstrated)

- **H1. A dense signal recovers the corroborating sessions.** Both peers that win on LongMemEval
  pair a local dense embedding with a lexical signal. The evidence sessions Agent Memory ranks at
  5–30 may share topic but not vocabulary with the question.
- **H2. Fusion promotes items that two signals both rank moderately.** RRF in Hindsight and the
  0.6/0.4 rerank in MemPalace do this.
- **H3. Ranking and return selection can be separated.**
  - The peers rank well but do not select (O4).
  - C1/C2 select better but lose depth recall, because the cut removes corroborating evidence
    (independent #819 review).
  - So a better ordering signal (H1/H2) and Agent Memory's return selection may be complementary
    rather than competing. This is the design space the review's "make sufficiency aware of
    evidence aggregation" points to.

## Demonstrated (attribution and a reproducible mechanism, not an intervention on Agent Memory)

### D1. On Agent Memory's recovered misses, a dense ranking alone finds the evidence

Source: `819-hindsight-arm-attribution/`. This covers 115 evidence sessions of the 44 recovered
questions.

| Places the evidence session in its top 5 | Share |
|---|---:|
| Hindsight's e5-small semantic arm alone | 95% |
| Hindsight's BM25 arm alone | 72% |
| Hindsight after RRF | 92% |
| Agent Memory | 54% |

For the 45 sessions that Hindsight ranks in its top 5 and Agent Memory ranks below:

- the semantic arm alone has 44 in its top 5;
- Agent Memory has 30 of them at ranks 6–10.

This supports H1, and it also shows Agent Memory's lexical ordering trailing a plain BM25 arm on
this evidence. Whether adding a dense signal would close the gap for Agent Memory is untested.
That needs an intervention by the runtime owner, and these observations are not tuning targets.

### D2. Hindsight's order instability comes from ties in its BM25 arm

Source: `../640-hindsight/full500/determinism-probe/`.

| Check | Result |
|---|---|
| Query-time recall, same bank | identical 10/10 |
| Fresh ingestion | reorders 8/10 |
| Returned set after fresh ingestion | same 10/10 |
| BM25-arm ranks changed | 10/10 |
| Semantic-arm ranks changed | 1/10 |

The cause is `ORDER BY ts_rank_cd(...) DESC` with no tie-breaking key over coarse, heavily tied
scores.

The lesson for Agent Memory is to keep a deterministic tie-break in any fusion it adopts. Agent
Memory's own repeats are bit-identical.

## Known evidence-identity limitations (independent review)

- **Recorded revisions can postdate a run's start.** Some exec and execution-identity records
  name the worktree HEAD captured *after* the run. The worktree received evidence-only commits
  while runs were in progress (for example, LangMem rep1 records `be5cade`). The bridge, worker
  and shim blobs named in each preregistration are unchanged at HEAD, so there is no effect on
  code. Future runs should record the revision at launch.
- **The Agent Memory baseline revision is recorded inconsistently** across control bundles.
  The rows are identical, 2000/2000.
- **Bridge discipline enforces gold isolation.** The LongMemEval interface passes each bridge
  the full dataset row, gold included. Reviewed bridges ignore it, but the interface does not
  enforce that.
