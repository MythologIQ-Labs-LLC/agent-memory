# #732 R6 provider freeze v2

This record freezes the provider configuration for the #732 R6 generalization
acceptance **before any provider credential is used and before holdout authoring**.

The earlier unaccepted v1 draft targeted the direct Anthropic Messages API and
therefore required an `ANTHROPIC_API_KEY`. The owner does not have or intend to
buy Platform API usage. No v1 credential was used, no holdout was authored, and
no score was observed. v2 supersedes that unaccepted draft before the
experimental boundary is crossed.

- provider: Claude Code CLI
- CLI: `2.1.294` / release `v2.1.294`
- model: `claude-sonnet-5-5`
- authentication: Claude subscription OAuth
- CI/script token, when needed: `CLAUDE_CODE_OAUTH_TOKEN`, generated by

- effort: `high`
- maximum prior-memory candidates: 8
- evaluator extractor version:
  `1.0.0/claude-code-2.1.294/claude-sonnet-5-5/high/9974ab010b12`

  `9974ab010b12fcd5b6e86352e4f269ab3b1e2f8842521e5b031b23904c1cd7b9`

The exact release artifacts are also pinned in `provider-v2.json` for Linux

## Runtime boundary

The Claude Code adapter is evaluation-only and implements the existing public
`PropositionExtractor` protocol. It does **not** modify Runtime Baseline v6.

That distinction matters: R6 is testing whether the accepted generic extractor
seam plus the frozen typed-proposition/currentness machinery generalizes when
fed by a real model. It is not permission to add a Claude-specific runtime
dependency.

The extractor remains opt-in. A caller must provide an explicit egress policy,
and extraction has `authority_effect: none`.

## Billing boundary

R6 must not use `ANTHROPIC_API_KEY` or `ANTHROPIC_AUTH_TOKEN`.

The accepted authentication path is the owner's Claude subscription OAuth,
either through an already authenticated local Claude CLI or a long-lived
`CLAUDE_CODE_OAUTH_TOKEN` generated by `claude setup-token` for a script/CI
environment.

A missing subscription entitlement or exhausted subscription limit is
`BLOCKED`, never a failed benchmark score.

## What this does not do

This freeze does **not** run a model, use an OAuth token, author the R6 holdout,
or score anything.

The next permitted operation is one synthetic smoke request using this exact
configuration. Only after that smoke evidence is accepted may the independent
holdout be authored.

Changing the CLI version, model, prompt, structured schema, effort, candidate
budget, tool/MCP posture, or authentication class after this freeze requires a
new provider-freeze identity. No existing holdout may silently migrate.

## Acceptance sequence

1. provider freeze;
2. subscription-OAuth smoke request;
3. fresh independent G6 holdout authoring;
4. holdout freeze;
5. one holdout scoring on published Runtime Baseline v6;
6. extractor-on MESA and #580/#584 regressions;
7. R6 acceptance or rejection.

#673 remains held through step 7.
